# スライド案と最終 HTML のレビューの細則

create/SKILL.md の 3 章の手順 3〜8 の細則。ページの構成・ボタンの扱い・回答の書式・再提示・統合・最終確認。コマンドと待ち受けのコードは SKILL.md にある。設計図と原稿の確認（`review-plan`）も、待ち方と回答の保存は同じ（保存先は `<名前>/source/answers-plan-N.md`）。

作業ファイルはすべて `<名前>/source/` にある。回答の保存先は、スライド案の回が `source/answers-N.md`、最終が `source/answers-final.md`。前回承認したスライドは、承認済みで開く（選択済み）。「承認」を押すと次のスライドへ移る。

## 手順 3: ページを開いて伝える（`variants`、設計図と原稿は `review-plan` の `plan-review.html`）

`python "${CLAUDE_PLUGIN_ROOT}/run.py" variants "<名前>"`（`--round` を省くと次の回） → `<名前>/source/variants.html`。Playwright MCP の `browser_navigate` で `file:///C:/.../variants.html` を開き、「左の一覧から 1 枚ずつ見て、型（A/B/C）か自由設計（R）を選び、続けてデザイン 1〜3 を選んで、画面下の『承認』か『要修正』を押してください。直したい点や、どの案でもない場合はコメントに書いて（案は選ばず『要修正』）、画面下の『回答をコピー』を押してください」と伝える。ページは、左に一覧（状態の点つき）、右に 1 枚ずつ縦に並べる（下の「表示の切り替え」のとおり）。案のサムネは、押すと大きく見える。見てほしい要素に付けた `data-note` は、「見どころ」にチェックを入れると枠と番号で重なる。スクロールして見る（1280×720〜1920×1080 で確認済み）。**`browser_resize` で窓の大きさを変えない**（窓とページの大きさがずれる）。案（型）の行の下に、選んだ案のデザイン 1〜3 の行がある（案を変えると中身が入れ替わる。デザインが 1 つだけの型は出ない）。案の下には型名、大きな画面の下には「型と選んだ理由」が出る（断片の `data-variant="型名｜理由"`）。自由設計の案 R は「案 R（自由設計）」で出て、デザインの選択（1〜3）は出ない。「承認／要修正」のボタンは画面下の固定バーにある。**承認**を押すと、案を選んでいなければ表示中の案が選ばれる。**要修正**は案を自動では選ばない（どの案でもない場合を含む。案を選ばずに要修正を押し、コメントに理由を書く）。1 案だけのスライドは承認／要修正のボタンだけで答える。**承認か要修正を押していないスライドは、回答に含まれない**（何も押していなければ「回答をコピー」は案内を出してコピーしない）。選んだラジオとボタンは、もう一度押すか「選択を外す」で外せる。

**表示の切り替え**: スライド上部の行に、「型と選んだ理由」「見どころ」「部位のバッジ」のチェックボックスが常にある（ページの並び順。全スライドで共通）。どれも初期はオフで、チェックで出る（見どころはピンクの番号枠と一覧、部位のバッジは部位ごとのコメント用）。前回のコメントと今回の直しは常に出る。ページの並びは、スライド → 見どころ・部位のコメント → 案・デザインの選択で、承認・要修正・コメント・選択を外す・前へ・次へ・回答をコピーは画面下に固定される。

**部位のバッジ**: 大きな 1 案には、断片の `data-part` の部位名が青いバッジで重なる（同じ部位が複数あるときは、左上から右下の順に ①②③。例: スティッカー②）。バッジを押すと「部位のコメント」の欄にその部位の入力行が開く（空の行は回答に出ない）。部位のコメントを書くと、承認も要修正も押していなければ「要修正」になる。バッジは `pp-*` ではなく、ページ専用（PPTX には出ない）。「部位のバッジを表示」で消せる。グラフ（`チャート`）は全体で 1 つのバッジで、凡例・データラベル・軸ラベルは、コメントの中で名前を使って指す。部位名の一覧と付け方は [html-rules.md](html-rules.md)。

## 手順 4: 「回答をコピー」を待つ

「回答をコピー」が押されるのを待つ（ユーザーに「完了」と入力させない）。押されると、回答はクリップボードに入り、同時に `window.__submitted` が立つ。`browser_evaluate` で次を実行し、送信されるか約 100 秒たつまでブロックして結果を返す。`submitted` が false なら同じ呼び出しを繰り返す（合計約 30 分、18 回まで）。18 回を超えても送信されないときは、続行方法（もう一度待つ／回答を貼り付けて渡す／中止）を利用者に質問して止まる。ユーザーがターミナルに入力したときは待ちをやめて、その内容に従う。

`() => new Promise(res => { const t0 = Date.now(); const id = setInterval(() => { if (window.__submitted || Date.now() - t0 > 100000) { clearInterval(id); res({ submitted: !!window.__submitted, md: window.__answersMd }); } }, 500); })`

## 手順 5: 回答の保存と書式

`submitted` が true なら、`md` を `<名前>/source/answers-N.md` に書く（N は何回目か）。待ち受けずに、利用者がチャットに貼り付けた場合も、貼られた md を同じように書く。回答の形式は `## SNN` / `- 選択:`（A/B/C。要修正で案なしなら空）/ `- デザイン:`（1〜3。省略時は 1）/ `- 判定:`（承認・要修正。空でもよい。古い回答にはない）/ `- コメント:` / `- 部位: 注釈 ／ コメント: 出典を足す`（部位ごとのコメント。何行でも。案が複数のスライドでは `- 部位: 案 A 注釈 ／ …`）。部位のコメントは、スライド全体のコメントと同じく、直して再提示するまで `finalize` を止める。`- 理由:` のような未知の行は読み飛ばされる。ボタンは「回答をコピー」の 1 つだけ（送信ボタンはない）。`finalize` は、判定が「要修正」のスライドも、コメントが残るスライドと同じく止める。

## 手順 6: 直して再提示する

**コメントがあるスライドだけ**、選ばれた案とデザインを直して 1 案にし（選ばれたデザインの内容で `NN-A.html` を上書き、`NN-B/C` と `NN-*-d2/d3` は削除。いずれも `source/slides/`）、`variants --round N+1`（省略すると次の回）で再提示する（「採用／要修正」の選択になる）。ページには全スライドが出るが、**利用者には直したスライドだけ答えてもらう**（ほかは前回の選択のまま。未回答でよい）。別案の希望があるときだけ 3 案に戻す。コメントが未反映のうちは `finalize` が止まる。再提示のページは、前回のコメントを `answers-N.md` から自動で出す。**直した内容は `<名前>/source/round-(N+1)-notes.md` に「NN: 直した内容」の行で書く**と、同じスライドの「今回の直し」として並ぶ（書かなくてもよい）。

## 手順 7: 統合する（`finalize`）

すべて決まったら、`python "${CLAUDE_PLUGIN_ROOT}/run.py" finalize "<名前>"`（`--answers` を省くと `source/answers-*.md` を回の順に全部使う） → `final.html`（`build` が使う素のページ。変えない）と、確認用の `final-review.html`。後の回答が前の回答を上書きし、選択が空のスライドは前の回答を消さない。

## 手順 8: 最終 HTML（`final-review.html`）は参照用

最終 HTML の承認は求めない（承認は、設計図と原稿、スライド案の選択の 2 回）。`finalize` のあと、そのまま `build` へ進む。`final-review.html` は、完成後に利用者が全体を見返す参照用で、部位のバッジも出る（直しは `revise`）。`finalize` を使わずにページだけ作り直すときは `review-final "<名前>"`（`--answers` を省くと `answers-*.md` を自動で使う）。
