# スライド案と最終 HTML のレビューの細則

create/SKILL.md の 3 章の手順 3〜8 の細則。ページの構成・ボタンの扱い・回答の書式・再提示・統合・最終確認。コマンドと待ち受けのコードは SKILL.md にある。設計図と原稿の確認（`review-plan`。利用者が頼んだときだけの任意の確認）も、待ち方と回答の保存は同じ（保存先は `<元データ>/answers-plan-N.md`）。

作業ファイルはすべて `<元データ>/` にある。回答の保存先は、スライド案の回が `<元データ>/answers-N.md`、最終が `<元データ>/answers-final.md`。前回承認したスライドは、承認済みで開く（選択済み）。「承認」を押すと次のスライドへ移る（前へ・次へのボタンはない。移動は左の一覧）。

## 手順 3: ページを開いて伝える（`variants`、設計図と原稿は `review-plan` の `plan-review.html`）

`python "${CLAUDE_PLUGIN_ROOT}/run.py" --data "${CLAUDE_PLUGIN_DATA}" variants "<元データ>"`（`--round` を省くと次の回） → `<元データ>/variants.html`。Playwright MCP の `browser_navigate` で `file:///C:/.../variants.html` を開き、「左の一覧から 1 枚ずつ見て、型（A/B/C）か自由設計（R）を選び、続けてデザイン 1〜3 を選んで、画面下の『承認』か『要修正』を押してください。直したい点や、どの案でもない場合はコメントに書いて（案は選ばず『要修正』）、画面下の『回答をコピー』を押してください」と伝える。ページは、左に一覧（状態の点つき）、右に 1 枚ずつ縦に並べる（下の「表示の切り替え」のとおり）。案のサムネは、押すと大きく見える。見てほしい要素に付けた `data-note` は、「見どころ」にチェックを入れると枠と番号で重なる。スクロールして見る（1280×720〜1920×1080 で確認済み）。**`browser_resize` で窓の大きさを変えない**（窓とページの大きさがずれる）。案（型）の行の下に、選んだ案のデザイン 1〜3 の行がある（案を変えると中身が入れ替わる。デザインが 1 つだけの型は出ない）。案の下には型名、大きな画面の下には「型と選んだ理由」が出る（断片の `data-variant="型名｜理由"`）。自由設計の案 R は「案 R（自由設計）」で出て、デザインの選択（1〜3）は出ない。「承認／要修正」のボタンは画面下の固定バーにある。**承認**を押すと、案を選んでいなければ表示中の案が選ばれ、次のスライドへ移る。**全部承認**は、まだ判定のないスライドのうち案が決まっているもの（1 案だけのスライドと、案を選んだスライド）を承認する。案が複数で未選択のスライドと、コメント（コメント欄か部位のコメント）を書いたのに判定のないスライドは残し、それぞれの数を画面に出す。次へは進まず、回答は 1 枚ずつ承認したときと同じ。**要修正**は案を自動では選ばない（どの案でもない場合を含む。案を選ばずに要修正を押し、コメントに理由を書く）。要修正には直す点が要る（コメント欄か、いずれかの部位のコメント。画面での文字の編集 `- 編集:` は数えない）。あれば判定が付いて承認と同じく次へ進む（最後のスライドでは動かない）。なければ判定は付かず、次へも進まず、案内（橙の文字）を出してコメント欄に移る。部位のコメントを書くと、判定がなければ自動で要修正になる（このときは次へ進まない）。自動で付いた要修正は、「要修正」を 1 回押すと確定して次へ進む（外れない）。押して付けた要修正は、もう一度押すと外れる。画面下の案内は、判定を付けたときと、スライドを移ったときに消える。1 案だけのスライドは承認／要修正のボタンだけで答える。**承認か要修正を押していないスライドは、回答に含まれない**（何も押していなければ「回答をコピー」は案内を出してコピーしない）。ただし、コメントを書いたのに承認も要修正も押していないスライドがあると、「回答をコピー」はそのスライドへ移って案内を出し、コピーしない（コメントが回答から落ちないように）。編集モードで文字を直した（`- 編集:` の記録がある）のに承認も要修正も押していないスライドも同じく止める（直しだけでは判定にならず、案が決まらないまま `finalize` で止まるため。リセットで元に戻した直しは数えない）。選んだラジオとボタンは、もう一度押すか「選択を外す」で外せる。

**表示の切り替え**: スライド上部の行に、「型と選んだ理由」「見どころ」「部位のバッジ」のチェックボックスが常にある（ページの並び順。全スライドで共通）。どれも初期はオフで、チェックで出る（見どころはピンクの番号枠と一覧、部位のバッジは部位ごとのコメント用）。前回のコメントと今回の直しは常に出る。ページの並びは、スライド → 見どころ・部位のコメント → 案・デザインの選択で、承認・要修正・全部承認・コメント・選択を外す・回答をコピーは画面下に固定される。

**部位のバッジ**: 大きな 1 案には、断片の `data-part` の部位名が青いバッジで重なる（同じ部位が複数あるときは、左上から右下の順に ①②③。例: スティッカー②）。バッジを押すと「部位のコメント」の欄にその部位の入力行が開く（空の行は回答に出ない）。部位のコメントを書くと、承認も要修正も押していなければ「要修正」になる（自動の要修正。「要修正」を 1 回押すと確定して次へ進む）。バッジは `pp-*` ではなく、ページ専用（PPTX には出ない）。「部位のバッジを表示」で消せる。グラフ（`チャート`）は全体で 1 つのバッジで、凡例・データラベル・軸ラベルは、コメントの中で名前を使って指す。部位名の一覧と付け方は [html-rules.md](html-rules.md)。

## 手順 4: 「回答をコピー」を待つ

「回答をコピー」が押されるのを待つ（ユーザーに「完了」と入力させない）。押されると、回答はクリップボードに入り、同時に `window.__submitted` が立つ。`browser_evaluate` で次を実行し、送信されるか約 100 秒たつまでブロックして結果を返す。`submitted` が false なら同じ呼び出しを繰り返す（合計約 30 分、18 回まで）。18 回を超えても送信されないときは、続行方法（もう一度待つ／回答を貼り付けて渡す／中止）を利用者に質問して止まる。ユーザーがターミナルに入力したときは待ちをやめて、その内容に従う。

`() => new Promise(res => { const t0 = Date.now(); const id = setInterval(() => { if (window.__submitted || Date.now() - t0 > 100000) { clearInterval(id); res({ submitted: !!window.__submitted, md: window.__answersMd }); } }, 500); })`

## 手順 5: 回答の保存と書式

`submitted` が true なら、`md` を `<元データ>/answers-N.md` に書く（N は何回目か）。待ち受けずに、利用者がチャットに貼り付けた場合も、貼られた md を同じように書く。回答の形式は `## SNN` / `- 選択:`（A/B/C。要修正で案なしなら空）/ `- デザイン:`（1〜3。省略時は 1）/ `- 判定:`（承認・要修正。空でもよい。古い回答にはない）/ `- コメント:` / `- 部位: 注釈 ／ コメント: 出典を足す`（部位ごとのコメント。何行でも。案が複数のスライドでは `- 部位: 案 A 注釈 ／ …`）。部位のコメントは、スライド全体のコメントと同じく、直して再提示するまで `finalize` を止める。画面の編集・配色・出力形式は次の行になる。`- 編集: {"f":"断片ID","t":"対象の ID","before":"…","after":"…"}`（`## SNN` の下に 1 行ずつ。JSON は 1 行）、`- 配色: navy|green|gray|#RRGGBB`・`- 出力形式: pptx|html|both`（先頭の front matter の直後に置く。読み込み時の選択から変えたときだけ出る）。`- 編集:` は `apply-edits` で断片へ反映すると、回答に `- 編集の反映: 済み` が足され、未反映のうちは `finalize` が止まる。反映できなかった編集（断片がない・対象が合わない・読めない行）は、`apply-edits` が標準エラーに列挙して終了コード 1 で終わる（反映できるものは反映し、反映済みの印も足すので止まり続けない）。入っていない編集は、断片か回答を直して `--answers <回答ファイル>` を付けて再実行するか、断片を手で直す。`apply-edits` と `finalize` のあとは `python "${CLAUDE_PLUGIN_ROOT}/run.py" --data "${CLAUDE_PLUGIN_DATA}" check "<元データ>/final.html"` で違反 0 件を確かめる（HTML だけの出力では `build` の検査が走らない）。`final-review.html` で直した編集は、「回答をコピー」した内容を `<元データ>/answers-final.md` に保存すると、同じ `apply-edits` の対象になる。`- 理由:` のような未知の行は読み飛ばされる。ボタンは「回答をコピー」の 1 つだけ（送信ボタンはない）。要修正なのにコメントも部位のコメントもないスライドと、コメントか画面での文字の直し（`- 編集:`）はあるが判定（承認・要修正）のないスライドがあるときは、「回答をコピー」は案内を出してそのスライドへ移り、コピーしない。`finalize` は、判定が「要修正」のスライドも、コメントが残るスライドと同じく止める。

## 手順 6: 直して再提示する

**コメントがあるスライドだけ**、選ばれた案とデザインを直して 1 案にし（選ばれたデザインの内容で `NN-A.html` を上書き、`NN-B/C` と `NN-*-d2/d3` は削除。いずれも `<元データ>/slides/`）、`variants --round N+1`（省略すると次の回）で再提示する（「採用／要修正」の選択になる）。ページには全スライドが出るが、**利用者には直したスライドだけ答えてもらう**（ほかは前回の選択のまま。未回答でよい）。別案の希望があるときだけ 3 案に戻す。コメントが未反映のうちは `finalize` が止まる。再提示のページは、前回のコメントを `answers-N.md` から自動で出す。**直した内容は `<元データ>/round-(N+1)-notes.md` に「S01: 直した内容」（S と 2 桁の番号。番号だけの行は読まない）の行で書く**と、同じスライドの「今回の直し」として並ぶ（書かなくてもよい）。

## 手順 7: 統合する（`finalize`）

すべて決まったら、`python "${CLAUDE_PLUGIN_ROOT}/run.py" --data "${CLAUDE_PLUGIN_DATA}" finalize "<元データ>"`（`--answers` を省くと `<元データ>/answers-*.md` を回の順に全部使う） → `final.html`（`build` が使う素のページ。変えない）と、確認用の `final-review.html`。後の回答が前の回答を上書きし、選択が空のスライドは前の回答を消さない。ただし、選択が空でも判定が「要修正」のスライド（案を選ばない要修正）は前の回答（承認を含む）を上書きし、直して再提示するまで `finalize` が「要修正です。直してから再提示してください: <コメント>」で止まる。

## 手順 8: 最終 HTML（`final-review.html`）は参照用

最終 HTML の承認は求めない（承認は、スライド案の選択の 1 回。設計図と原稿に人の承認の関門はない）。`finalize` のあと、そのまま `build` へ進む。`final-review.html` は、完成後に利用者が全体を見返す参照用で、部位のバッジも出る（直しは `revise`）。`finalize` を使わずにページだけ作り直すときは `review-final "<元データ>"`（`--answers` を省くと `answers-*.md` を自動で使う）。
