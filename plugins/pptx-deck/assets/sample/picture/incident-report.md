# 障害報告（架空）: 受注システムのログイン遅延

`diagram` の入力素材の見本（文書起点）。架空の会社・架空の障害で、実在の情報は含まない。ここから、障害動作（想定動作と想定外動作）とトラフィックフローの絵を起こす。

## 概要
- 事象: 受注システムのログインが、利用者から見て「画面が固まる」状態になった。
- 影響: 営業部の利用者（xx 名）がログインできなかった。時間帯は xx 時〜xx 時。

## システム構成
- 利用者の端末から、社内 LAN の FW を通り、LB が Web サーバ 2 台へ振り分ける。
- Web サーバは AP サーバへ処理を渡し、AP サーバが DB を参照して応答を返す。

## 想定していた動作
1. 利用者がログイン要求を送る。
2. Web サーバが AP サーバへ転送する。
3. AP サーバが DB を参照する。
4. 応答を返す（xx 秒以内）。

## 実際に起きた動作（想定外）
1. 〜 2. は想定どおり。
3. DB が無応答だった。AP サーバは待ち時間の上限がなく、待ち続けた。
4. xx 秒後に AP サーバの接続が切れ、利用者にはエラー画面が返った。

## 調査で分かったこと
- 調査中、Web サーバから DB への直接の接続（想定していない経路）が xx 件見つかった。
- DB への入口は AP サーバだけにする設計だった。

## 未確定
- 待ち時間の実測値、影響した利用者数、接続が見つかった時期。
