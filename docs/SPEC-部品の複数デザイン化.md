# SPEC: 全部品の複数デザイン化（1型につき3デザイン）

作成: 2026-10-13 · 状態: 承認済み（2026-10-13。選択画面は型→デザインの2段で1枚、見本は1ファイルのまま） · 前提: [SPEC-ページ枠の統一とPDF準拠](SPEC-ページ枠の統一とPDF準拠.md)（完了・73本が新枠）

## 目的

PDF「パワーポイントのデザインパターン大全」は、各パターンに「デザインパターン1・2・3」の3種を載せている。これに合わせ、部品庫の**全部品を3デザイン**にする。同じ型（情報の構造）のまま、見た目の形だけを選べるようにして、利用者が型を選んだあとにデザインを選べる流れにする。

## 決定事項（2026-10-13 利用者回答）

| 項目 | 決定 |
|---|---|
| 見本のグルーピング | 今の4区分（グラフ・図解・レイアウト・表）のまま。PDFの分類には寄せない |
| デザインの数 | 全パターン3デザイン（PDFと同じ） |
| 運用 | 3案は今のまま型違い（密度違いの案は出さない）。型を選んだあとにデザインを選び、その結果を返す。選択の画面（HTML）は型とデザインで分けない |

## 定義

- **パターン**＝部品庫の1部品（型）。73本すべて。note 版・`effort-bar`・`quote-bridge` も1本として数える。
- **デザイン**＝同じ型・同じ情報量のまま、図形の形・並べ方・強調の置き方を変えたもの。デザイン1＝今の部品。デザイン2・3を新規に作る。
- 変えないもの: ページ枠（題・リード文の帯・図表タイトル・注）、配色、フォント、本文の下限（14pt）、要素数と必須データ。変えるのは本体の形だけ。
- 密度違い（要素を減らす・文を詰める）はデザイン違いと認めない。デザイン1〜3は同じ原稿をそのまま差し替えられる。

## 構成（案）

| 項目 | 案 |
|---|---|
| ファイル名 | デザイン1＝`<型>.html`（今のまま）、デザイン2・3＝`<型>-d2.html`・`<型>-d3.html`。同名の既存部品がないことを確認する |
| 本数 | 73 → 219本（追加146本）。区分別: グラフ 10→30、図解 32→96、レイアウト 15→45、表 16→48 |
| 先頭コメント | デザイン2・3にも、用途と差し替える所を書く。デザイン1との違い（形の特徴）を1文で添える |
| 部品見本.html | 4区分のまま、型ごとに3デザインを横に並べる。1枚の画像は約9.6MB÷73で約130KB のため、全219本で約29MB。1ファイルで開けるが重い場合は、画像を縮小して軽くする（要確認） |
| 全件チェックの補助 | 見本の各デザインに「型名／デザイン番号」を表示し、利用者が指摘するときの呼び名にする（`bar` の2＝`bar-d2`） |

## 選択の流れ（variants）

1. 今のとおり、3案（A＝第1候補、B＝次点1、C＝次点2）は型違いで出す。
2. 利用者が選んだ型について、デザイン1〜3を同じ原稿で描画して見せる。
3. 回答は、案の選択に加えて**デザイン番号**を返す（`- デザイン: 2`。省略時は1）。選択の画面は1枚で、型の案とデザインを並べて選べる（実装の形は着手前に確認）。
4. `finalize` は、選ばれた型とデザインの HTML（`-d2`・`-d3` を含む）で確定する。

## 受入条件

1. 73型すべてにデザイン2・3があり、全219本が `check` の違反0件。
2. デザイン2・3は、デザイン1と同じ原稿（要素数・必須データ・文の量）を差し替えて入る。本文は14pt以上。
3. 3デザインの形が、見た目で区別できる（同じ図形の寸法違いだけにしない）。
4. 全件を LibreOffice の描画で目視確認する。PowerPoint 実機の確認は利用者に依頼する。
5. 部品見本.html が4区分で3デザインを並べ、全件の呼び名が表示される。
6. `variants` が、選ばれた型のデザイン1〜3を見せ、`parse_answers` が `- デザイン:` を読む。`finalize`→`build` で選ばれたデザインが使われる。
7. SKILL.md・README・`components.md`・`patterns.md`・`review-flow.md` の本数（73→219）と流れを更新し、`grep` で食い違いを確かめる。

## 非目標

- PDFの分類（要素間の関係あり／なし／ページ項目別）への並べ替え。
- 配色・フォント・ページ枠の変更。
- PDFの画像・文章の転用（形だけ自前で作る）。
- 型の追加・統合（73型の増減はしない）。
- デザイン違いを3案（A/B/C）に混ぜること。

## 進め方（案）

1. 区分ごとに、デザイン2・3を作る（レイアウト → 表 → グラフ → 図解の順を想定）。区分ごとに `check`・描画確認・コミットし、見本を更新して利用者が確認する。
2. 全区分が終わってから、コード（`variants`・回答の解析・`finalize`）と文書を更新する。
3. 利用者の目視確認は、区分ごとの見本更新のたびに受ける。
