# 部品見本の点検結果（71 型 213 本）

作成: 2026-10-13 · 状態: 利用者の判定待ち · 対象: `部品見本.html`（コミット a6b61ff 時点）の全 213 枚を描画画像と先頭コメントで点検

点検の観点は 5 つ。1 不要な部品、2 統合できる部品、3 視線誘導・ロジック、4 部品の説明、5 グルーピング。1・2・5 は「判定」列に **採用／不採用／保留** を書いてください。3・4 は、判定がなければそのまま直します（直さない項目があれば「直さない」と書いてください）。

## 3 視線誘導・ロジック（直す候補）

### 3.1 主張と強調がずれている（優先度 高）

| 部品 | 問題 |
|---|---|
| `layers` ×3 | 濃い面が「監視済み」側にあり、リード文「未監視 55% が問題」と強調が逆。未監視側は白と淡色で最も目に入らない |
| `formula` ×3 | 運用 0.6 の面が機器 0.9 より濃く、強調色を置いた機器より運用に目が行く |
| `hbar` d1 | リード文は「3 拠点に集中」だが強調は東京 1 本。d2 の右パネル（昨年比）は別の論点を持ち込む |
| `quote-bridge` d1 | 主役「保守▲1,000」が設計▲900 と同じ濃灰で、結論が本体から読めない |
| `waterfall` d1 | 全項目が同じ濃灰で「回線と運用委託」を特定できない。最後に合計がなく 20 で宙に浮く |
| `incident` ×3 | 強調は「10.0 時間」だが、主張は「うち 5 時間は待ち」。5h は小文字と注にしかない |
| `summary` d1 | リード文は②③の 2 指標、強調は②「90」のみ。90 は指数で、意味は小文字の「▲1.2 億円」側にある |
| `delta` d1 | 強調 1 点が合計「+122」にあるが、主張は +26・+96。合計は台と本を足した数で単位混在 |
| `issues` d1 | 強調 1 点が No.3（中・期限超過）にあり、リード文（重要度高は解消できる）と別の話題 |
| `actions` d1 | 強調（期限確定）と主張（恒久策 3 件）が直接つながらない |
| `spec` d1 | 太字 1 行（⑥戻し手順）が主張（6 項目すべてが数値基準）と別の点に目を引く |
| `decision` ×3 | 右下の「6.0 億円／70%／5 年以内」が最大の文字で、承認対象より先に目が行く |
| `gantt` d1 | 左のフェーズ見出し 4 つが濃い面で、◆（強調色）が埋もれる |
| `area` ×3 | 強調枠（委託範囲）とベンダー行の濃い帯が競合し、濃い意味が凡例なしで読めない |

| `pyramid` d2・d3 | 上位層を濃い基調色で塗っており、d1 コメントの「大きな面に濃い基調色は使わない」と不整合 |
| `rating` d2・d3 | 打ち手 3 行がすべて基調色の太字で、「要の 1 点だけ」の原則に反する |
| `effort` d1 | 「▲140」が強調色と紺太字の 2 か所に出る |
| `cost` d1 | 太字が 5 か所あり、コメントの「最大の費目のセルだけ太字」より多い |
| `stacked` d3・`quote-bridge` d3・`enclosure` d3・`tree` | 強調が 2 点、または強調色ゼロで視線が止まらない |

### 3.4 ページ枠の不統一

- `decision`・`summary`・`rating` は注がなく論点帯で終わる。`incident` は注と含意が同じ行（charts は別行）。
- `decision` ×3 は「塗り＝承認する当日、枠線＝計画」の凡例文が本体に露出し、図表タイトルが内容の列挙になっている。
- `cycle-4` の KPI 帯だけ全幅で、`cycle-2/3` は中央 600px。

## 5 グルーピングの見直し（案）

今の 4 区分（グラフ・図解・レイアウト・表）は「作り方」の区分で、型を選ぶ人の問い（何を見せたいか）と合っていない。PDF の分類（関係あり／なし／ページ項目）と点検担当 4 名の案をもとに、**問いで分けた 9 区分**にする。統合 A〜P をすべて採用した後の型名で書く（採用しない場合は元の型名が入る）。

| 区分（問い） | 型 |
|---|---|
| 1 ページの骨格 | `cover`・`agenda`・`section`・`closing` |
| 2 判断を求める・要約する | `decision`・`summary`（障害版を含む）・`decisions`（旧 compare）・`options`・`argument`（旧 rating）・`raci` |
| 3 同格のものを並べる・位置づける | `parallel`・`positioning`・`venn`（overlap を含む）・`text`（見出し／Q&A／アイコン）・`screenshot`（並列／手順／拡大） |
| 4 前後・左右で比べる | `compare-ba`（before-after 系＋side-by-side）・`delta`（前後の数値表。quote-compare・site-matrix の合計を含む） |
| 5 順を追う（手順・段階・繰り返し） | `flow-h`・`flow-v`・`flow-text`・`flow-box`・`swimlane`・`steps`・`cycle-2`・`cycle` |
| 6 時間で測る | `timeline`・`gantt`・`roadmap` |
| 7 構成・範囲を見せる | `architecture`（layers を含む）・`topology`・`org`・`enclosure`・`area`・`site-matrix` |
| 8 要因・内訳に分解する | `tree`・`cause`・`formula`・`funnel`・`pyramid`・`relation` |
| 9 数値で見せる | グラフ: `bar`・`hbar`・`line`・`stacked`・`pie`・`waterfall`（quote-bridge を含む）／表: `cost`・`quote`・`effort`・`spec`（result を含む）・`actions`（issues・risk を含む） |

判定: 　　　（採用／区分の数や見出しを変える／今の 4 区分のまま）

補足
- 区分 9 の表は「数値で見せる」と「対応一覧」で性格が違うので、区分 2 または 5 に動かす案もある。
- `部品見本.html` の見出しと `patterns.md` の見出しを、この区分にそろえる。
