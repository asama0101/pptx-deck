# グラフ選択の最適化 SPEC

`2026-10-11_2215_pptx-skill-rev.md` の「グラフ」の決定（3 種・積み上げ棒は除外）を、この SPEC で更新する。食い違う箇所は、この SPEC を正とする。

## 概要
- 目的: 見た目でデータの関係が分かるグラフを選べるようにする。現状は型の一覧しかなく、「内訳と合計」のようなデータに合う型が選べない。
- きっかけ: 稟議書の資料で、内訳（3,800 万円＋2,000 万円）と合計（5,800 万円）を別々の棒で並べてしまい、合計が内訳の和だと伝わらなかった。

## 決定事項
- 型を追加する: `stacked`（縦の積み上げ棒）、`stackedh`（横の積み上げ棒）。系列を複数持てる。
- 入力形式: `{"type":"stacked","labels":[カテゴリ…],"series":[{"name":"系列名","values":[…]},…],"highlight":系列の番号}`。`stacked` と `stackedh` だけ `series` を使い、`values` は使わない。他の型は従来どおり。
- 色: `highlight` の系列だけアクセント色、他の系列は無彩色の濃淡（`#BFBFBF`、`#D9D9D9`、`#A6A6A6` の順）。セグメントの値ラベルと凡例を表示する。
- 選び方の指針を `SKILL.md` に書く（下表）。作者はデータの関係から型を選び、選んだ理由を原稿の「図解かグラフの指定」に 1 行で書く。
- 型の数は 6 種になる（`bar`、`barh`、`line`、`pie`、`stacked`、`stackedh`）。`SKILL.md` の「3 種」は誤記なので直す。

| データの関係 | 型 |
|---|---|
| 時間の推移 | `line` |
| 項目どうしの大小の比較（項目が少ない） | `bar` |
| 項目どうしの順位・長い項目名の比較 | `barh` |
| 全体に対する構成比（3〜5 項目） | `pie` |
| 内訳と合計を 1 つの棒で見せる | `stacked`（縦）／`stackedh`（横） |
| 複数の期間・項目で内訳の構成を比べる | `stacked` |

## 非目標
- ウォーターフォール: PowerPoint のネイティブチャートで系列別にラベルを消せず、編集可能な形で安定して作れないため入れない。内訳と合計は積み上げ棒で示す。
- 第 2 軸、100% 積み上げ、散布図、レーダー: 入れない。
- 3D、影、グラデーション: 使わない。

## 受入条件
1. `stacked` と `stackedh` を含む HTML を `check` と `build` に通せる。PPTX にネイティブの積み上げチャートが出て、`validate` 相当の検査（`packageErrors`）が空になる。
2. HTML プレビューのチャートが、積み上げ棒を描く（近似）。
3. 未対応の型、`series` の長さが `labels` と合わない入力は、原因を示すエラーで止まる。
4. `catalog.html` に積み上げ棒の見本が加わり、`check` が違反 0 件で通る。
5. `SKILL.md` に選び方の表と、積み上げ棒の書き方がある。
6. `npm test` がすべて通る（新しい型のテストを含む）。
7. 今回の稟議書の資料（`deck-work/cloud-migration`）の 8 枚目が、積み上げ棒に変わり、`check` に通る。
8. LibreOffice の画像で、積み上げ棒が崩れていないことを目で確認する。

## 影響範囲
`scripts/measure.js`（型の検証）、`scripts/build.js`（チャート生成）、`design/chart-preview.js`（プレビュー）、`design/catalog.html`（見本）、`SKILL.md`、`tests/`、`deck-work/cloud-migration/deck.html`。
