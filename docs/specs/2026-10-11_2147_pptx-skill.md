# PPTX作成スキル SPEC

## 概要
- 目的: テーマまたは原稿から、AI っぽくない・編集可能な .pptx を高品質に作る Claude Code スキルを作る。
- ゴール（完了判定）: 受入条件（下記）をすべて満たす。
- 配布形態: 他人にも配布できる形。このフォルダ（`C:\Users\sioay\OneDrive\github\pptx-create`）を git リポジトリにし、プラグイン構成（`.claude-plugin` + `skills/`）で作る。外部公開は完成後に別途判断し、承認を取る。
- 対象 OS は Windows のみ。Mac は対象外とする。
- 公式 `anthropic-skills:pptx` には依存せず、独立したスキルにする。description で「資料作成・デザイン品質」を担当範囲として明示する。

## 流れ
1. 入力: テーマのみ／Markdown・テキスト原稿のどちらでも受ける。
2. ①構成案（スライド一覧とメッセージ）を作り、承認を得る（入力が原稿なら省略可）。
3. ②Markdown 原稿を確定し、承認を得る（内容を凍結）。
4. 内容レビュー（論理の流れ・抜け漏れ・読み手視点）を原稿確定の段階で1〜2回行う。
5. ③HTML プレビューを作り、承認を得る（デザイン確定）。HTML は決められたクラスだけを使う制限付きとする。
6. PPTX は最後に1回だけ出力する。Playwright で HTML を描画し、各要素の位置・サイズ・フォント・色を DOM から計測して、pptxgenjs でネイティブの図形・テキスト・チャートに写す（DOM 計測型）。画像化は原則しない。
7. 体裁チェック（はみ出し・重なり・最小フォントサイズ・色数・余白）を行い、自動修正する。
8. ④出力後の最終確認として、体裁チェック結果を提示する。

## 仕様の決定事項
- 入力: テーマのみ／原稿。既存 PPTX の修正・再デザイン、Word/PDF/Excel の変換は初版の対象外。
- デザイン（テンプレなし）: 既定デザインシステムを1つ内蔵する。配色は無彩色＋アクセント1色（アクセント色は指示で変更可）。フォントは BIZ UDPゴシック。未導入の Windows 環境向けに代替として游ゴシック／メイリオを明示する。サイズ階層は数値で固定する（目安: タイトル24〜28pt、リード18〜20pt、図解部14〜16pt、階層間は4pt以上差）。
- テンプレ（.pptx/.potx）あり: 各レイアウトの寸法・スタイルを読み取り、同じ幾何の HTML レイアウトを自動生成する。本文は該当プレースホルダへ入れ、図解など自由配置部分は図形として追加する。配色・フォント・背景はテンプレに従う。
- 図解: 型のカタログ（ツリー、ピラミッド、フロー、サイクル、マトリクス、ベン図など）を HTML 部品として用意し、内容から型を選ぶルールを SKILL に持たせる。初版は主要な数種類に絞る。
- グラフ: PowerPoint のネイティブチャート（編集可能）にする。注目データだけ有彩色、他は無彩色にする。
- 確認手段: 幾何検査（DOM 計測）は常に実施する。画像化は任意機能とし、PowerPoint（COM）があればそれ、なければ LibreOffice、どちらもなければ幾何検査のみとする。
- 実行環境: Node（この PC は v24.13.1）と Playwright が前提。pptxgenjs は PPTX の新規生成に使う（導入が必要。公式 pptx スキルも新規作成に pptxgenjs を使っており、同じ方式）。初版は新規作成のみなので、既存 PPTX の編集機構（公式スキルの XML 直接編集）は持たない。テンプレの読み取りは、PPTX を zip 展開して XML（レイアウト・テーマ）を解析する方式とする。

## 受入条件
- サンプル依頼3種（テーマのみ／長めの原稿／図解・グラフ多め）で、10〜15枚の PPTX が生成できる。
- 幾何検査で、はみ出し・重なり・最小フォントサイズ違反が0件。
- 生成した PPTX の文字・図形・グラフが PowerPoint 上で編集できる（画像化された本文がない）。
- ユーザー自身の目視で「AIっぽい」と感じない（テンプレ感・階層なし・無意味な余白・文脈なし・単調、の5条件）。

## 非目標（初版）
- 既存 PPTX の修正・再デザイン。
- Word/PDF/Excel など他形式からの変換。
- 多役レビュー（ファクトチェック・敵対的レビュー、最大5ラウンド）。
- 複数デザインプリセット、毎回のデザインシステム生成ヒアリング。
- 外部への公開（完成後に別途判断）。

## リスク
- AI っぽい見た目: 既定デザインの数値ルール、図解カタログ、体裁チェックで対処する。
- 文字のはみ出し・日本語の改行崩れ: 幾何検査と、画像化（利用可能な環境のみ）で対処する。
- 編集しづらい PPTX: 画像化をせず、ネイティブ図形・チャートに統一する。
- フォント環境差: BIZ UDPゴシックは Windows 10 以降に入っていることが多いが、受け手の環境で未導入だと別フォントに置換され、折り返しや幅が変わる恐れがある。代替フォントを明示し、幾何検査は余裕をもたせた幅で行う。
- DOM 計測型は使える HTML/CSS に制約が出る（グラデーション・複雑な影などは非対応）。デザインシステムに沿った HTML のみ書くルールで吸収する。
- テンプレのレイアウト解析と HTML 自動生成は実装が複雑。初版で最も重い部分になりうる。
- PowerPoint COM はこの PC で未登録。実機で動くか未確認（任意機能のため必須ではない）。
- PPTX を何度も再生成するとトークンを消費する。承認点で止めて再生成を減らす。
- 環境依存: Windows 専用（Mac は対象外）。PowerShell/COM など Windows 固有の機能を前提にしてよい。

## 決定ログ
- Q1: ゴールは B（自動チェック・修正ループ込み）。テンプレがあればそれを参照する。
- Q2: 障壁は、AIっぽさ・はみ出し・編集しづらさ・フォント環境差。
- Q3: 配布できる形にする。追加インストールは許容する。
- Q4: MD→HTML→ネイティブ PPTX（方式 B）。
- Q5: 入力はテーマ・原稿。のちに Q13 で既存 PPTX 修正を取り下げ。
- Q6: テンプレはプレースホルダ流し込みが基本。
- Q7: 既定デザインシステムを1つ内蔵する。
- Q8: レビューは体裁チェックと内容レビュー。
- Q9: DOM 計測型（制限付き HTML → pptxgenjs）。
- Q10/Q15: 画像化は任意機能（PowerPoint COM → LibreOffice → 幾何検査のみ）。
- Q11: 公式 pptx スキルとは独立。
- Q12: git リポジトリ＋プラグイン構成。公開は後で判断。
- Q13: 既存 PPTX 修正は取り下げ。
- Q14: 図解カタログ＋ネイティブチャート。フォントは標準フォントの案だったが、v1 レビューで BIZ UDPゴシックに変更。
- v1 レビュー: フォントを BIZ UDPゴシックに変更。pptxgenjs の位置づけを確認（新規作成に使用、編集は対象外）。
- Q16: テンプレ時は、レイアウトの幾何を読み取って HTML を自動生成する。
- Q17: 承認点は ①構成案 ②MD 原稿 ③HTML プレビュー ④出力後の確認。
- Q18: 受入条件は A〜D の4つ。
- 承認後の追記: 対象 OS は Windows のみ（Mac は対象外）。

## 要確認事項
- Q16 でテンプレ対応を選んだが、Q18 の受入条件に「テンプレを渡したとき配色・フォント・背景が従う」を含めなかった。含めるか、テンプレ対応を初版の努力目標に留めるかを決めてほしい。この SPEC では「テンプレ対応は仕様に含めるが、受入条件には入れていない」状態になっている。
- BIZ UDPゴシックは、この PC の `C:\Windows\Fonts` に `BIZ-UDGothicR.ttc` があり、その中に含まれる想定だが、フォント名として PowerPoint から選べるかは未検証。実装時に確認する。
- 初版の図解の型は、主要な数種類に絞るとしただけで、具体的な種類は未決定。実装計画の段階で決める。
