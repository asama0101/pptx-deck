# SPEC: ページ枠の統一と、全部品のPDF準拠

作成: 2026-10-13 · 状態: 承認済み（2026-10-13） · 前提: [pptx-deck 修正計画](pptx-deck%20修正計画.md)（フェーズ1は完了・コミット済み）

## 目的

PDF「パワーポイントのデザインパターン大全」の構成に合わせて、全スライドの**ページ枠**を統一し、全部品（既存51本と新規）の**本体の形**をPDFに寄せる。これにより、型を差し替えても枠が変わらず、3案（型違い）の比較が本体の形だけの比較になる。

## 決定事項（2026-10-13 利用者回答）

| 項目 | 決定 |
|---|---|
| タイトルとリード文 | 2段構成に変更。**タイトル＝短い題（名詞句）**、**リード文＝判断を言い切る1文**。現行の図表タイトルはオブジェクト範囲の先頭に移す |
| コピーライト | 利用者が指定した文字列を左下に出す（既存の `footer` 設定を使う）。未指定なら空欄 |
| 修正の範囲 | 枠の統一＋本体の形。配色・フォント・余白は現状維持（修正計画の決定事項4を維持） |
| 新規部品 | 全パターンが対象（決定事項3）。パターンごとに比較用HTMLを出し、利用者が選んでから確定（決定事項2） |

## 新しいページ枠

PDF p3 の構成（タイトル・リード文・オブジェクト配置範囲・コピーライト／ページ番号）に合わせる。座標は 1280×720px。

| 要素 | 位置（案） | 内容と規則 |
|---|---|---|
| タイトル | 左64・上40・幅1152・高さ44（1行） | そのページの題。名詞句、20字以内。判断は書かない（例「SD-WAN更改の効果」） |
| リード文 | 上88〜90・帯の高さ80〜92（2行まで。サイズは承認待ち） | 判断を言い切る1文、30〜60字（現行の見出しの規則を移す）。「1スライド1メッセージ」 |
| オブジェクト範囲 | 上156〜下640 | 図表タイトル（対象・期間・単位）を先頭に置き、本体、注（末尾に「→ 含意」）の順。現行の「本体は下端まで使う」を維持 |
| コピーライト | 左下 | 利用者指定の文字列。現行のフッター日付は出さない |
| ページ番号 | 右下 | テンプレートのページ番号プレースホルダ |

既存部品の座標は、タイトルの位置が同じで、リード文が増え、図表タイトルが約10px下がるため、本体を約10px詰める再配置になる（見込み。実機で未確認）。

## 受入条件

1. 全部品（既存51本と新規）が、新しいページ枠で `check` の違反0件。
2. 全部品の先頭コメントに、新しい枠の使い方（タイトル・リード文・図表タイトルの役割）が書いてある。
3. `script.md` の規則を新しい枠に合わせる: `lint-script` が、タイトル（20字以内・名詞句）とリード文（30〜60字）を検査する。旧形式の原稿は、エラーではなく移行の案内を出す。
4. `build` が、タイトルをタイトルのプレースホルダ、コピーライトをフッターのプレースホルダへ出し、日付プレースホルダは出さない。利用者のテンプレートの場合も同じ。
5. SKILL.md・README・`components.md`・`html-rules.md`・`head-rules.md`・`review-flow.md`・`assets/sample/` が新しい枠と整合している（本数や用語の食い違いを `grep` で確かめる）。
6. 見本（`assets/sample/`）を新しい規則で作り直し、`variants`→`finalize`→`build` を通す。LibreOfficeの画像で崩れがない。`部品見本.html` を作り直す。
7. 本体の形をPDFに寄せた部品は、すべて利用者が比較ページで案を選んだものだけにする。

## 非目標

- 配色・フォント・余白の規則の変更。色の3役、強調色1点、ダッシュ禁止、本文14pt以上は維持する。
- PDFのページ画像・文章・アイコンの転用。形だけを自前で作る。
- 既存PPTXの編集、利用者テンプレートの本文スライドの流用（従来どおり対象外）。
- テンプレートのマスター／レイアウト自体の作り替え（座標が合わないテンプレートは、`check` の指摘で知らせるだけ）。

## リスク

- リード文の追加で本体の高さが約10px減る。表や密な図で収まらない部品が出る可能性がある（実機で未確認）。
- 利用者のテンプレートでタイトルとリード文の位置が合わない場合がある。`check` の `keepout` で知らせる。
- 部品の見た目を一括で変えるため、利用者の好みと外れると作り直しが大きい。まとまりごとの選択で手戻りを抑える。
- 旧形式の `script.md`（見出し1つ）との互換。移行の案内で扱い、エラーにはしない。

## 確認済み（2026-10-13）

1. リード文はタイトルの直下で左寄せ（Z の法則に従う）。
2. 現行のフッター日付は出さない。コピーライトは左下、ページ番号は右下。

## フェーズ0の実装方針（枠）

| 対象 | 方針 | 状況 |
|---|---|---|
| フッター | 日付プレースホルダは出さない。フッター（コピーライト）は左下・左寄せ、ページ番号は右下。`init --footer "…"` で文字列を指定し、未指定なら空欄 | 実装済み（`pptxutil.py`・`template.py`・`initdir.py`・`cli.py`、`standard.potx` のフッターを左寄せ） |
| `build` | 題（`data-role="title"`）→ タイトルのプレースホルダ。リード文（`data-role="lead"`）→ テキストボックス。コピーライト→ フッターのプレースホルダ | 既存の動作のまま使える（確認済み） |
| `check` | 本文スライドにリード文（`data-role="lead"`）がないときは警告 | フェーズ3 |
| `script_lint` | 「見出し」の規則（30〜60字）を「リード文」に移し、「題」（20字以内・名詞句）を足す。旧形式は移行の案内 | フェーズ3 |
| 部品 | 題（上40・高さ44）、リード文（上92〜100・最大2行）、図表タイトル（上160）、本体（上196〜590）、注（上598〜） | フェーズ2 |
