# pptx-deck

稟議書・提案書・計画書を作る担当者向けの Claude Code プラグイン。テーマや素材を渡し、画面でスライド案を選ぶと、コンサル資料のテイストの、編集できる PowerPoint（.pptx）ができる。

## 機能

- 入力は、テーマ・素材（メモ・文書・データ）・既存の Markdown 原稿のどれでもよい。Claude が、設計図（資料全体の結論と論点）と原稿を書く。
- スライド 1 枚ごとに、型の違う 3 案と、自由設計の 1 案（R）を並べて見比べられる。
- 人が承認するのは、スライド案を選ぶ 1 回だけ。直したい点は、コメントか、画面上での文字の打ち換えで伝える。
- 本文は画像にせず、PowerPoint の図形・文字・表・グラフで出す。できあがった PPTX は、PowerPoint で直せる。
- 配色・文字サイズ・出力形式を、選択画面で変えられる。
- 型に当てはまらない図（NW 構成図・障害の動作）は、`diagram` で SVG の絵にして貼れる。絵の中身は、PowerPoint で直せない。
- 自分の PowerPoint テンプレート（`.potx`・`.pptx`）の、表紙・章扉・目次・ヘッダー・フッターの上に作れる。

## 前提条件

- OS: Windows。
- Python 3.10 以上（`python` が PATH にあること）。
- Claude Code。
- ネットワーク: 初回に、Python のライブラリと Chromium（数百 MB）を取得する。
- 推奨: BIZ UDPゴシック。未導入だと、PowerPoint で文字の折り返しがずれることがある。
- 推奨: Claude Code の Playwright MCP。開始ページとスライド案の選択結果を、Claude が自動で受け取るために使う。なければ、コピーした回答をチャットに貼り付ける。
- 最終確認: Microsoft PowerPoint。確認用の画像は、HTML を撮影したもので、PowerPoint の実描画ではない。

## 導入方法

Claude Code で、次の 3 つを順に実行する。

```
/plugin marketplace add asama0101/pptx-deck
/plugin install pptx-deck@pptx-deck
/reload-plugins
```

`/reload-plugins` のあと、スキルの一覧に `pptx-deck:create` などが出れば、導入できている。

### ローカルに落として導入する

GitHub から直接導入しないときは、リポジトリを手元に clone し、そのフォルダを配布元として登録する。

```
git clone https://github.com/asama0101/pptx-deck.git
```

Claude Code で、clone したフォルダの絶対パスを指定する。

```
/plugin marketplace add C:\Users\<ユーザー名>\...\pptx-deck
/plugin install pptx-deck@pptx-deck
/reload-plugins
```

注意: 導入元は clone したフォルダそのものなので、`git checkout` でブランチを切り替えたり、フォルダを移動・削除したりすると、導入したプラグインの中身も変わる（動かなくなる）。

### 更新

新しい版は、[Releases](https://github.com/asama0101/pptx-deck/releases) で確認できる。次を実行すると、更新される。

```
/plugin marketplace update pptx-deck
```

ローカルに落として導入したときは、先に `git pull` を実行する。

### 初回の準備

初回の `/pptx-deck:create` で、Python の専用環境と Chromium を導入してよいか、確認される。承認すると自動で作られる。システムの Python には、何も入れない。

環境の状態は、Claude に「pptx-deck の環境を確認して」と頼むと、確認できる。何も変更しない。足りないものがあれば、案内が出る。

### アンインストール

Claude Code の `/plugin` からアンインストールする。

- 消える: 専用環境（`~/.claude/plugins/data/pptx-deck-<マーケットプレイス名>/`）。
- 残る: 作った成果物（出力先の `<成果物名>.pptx` と `pptx-deck-source/`）。
- 残る: Playwright の Chromium（ほかのツールと共有する場所。既定は `%LOCALAPPDATA%\ms-playwright`）。
- 残ることがある: 確認用の画像の一時フォルダ（`%TEMP%\pptx-deck\`）。

## 使い方

Claude Code で `/pptx-deck:create` を実行するか、「稟議資料を作って」のように頼む。

```
/pptx-deck:create 新サーバー導入の稟議資料を作って
```

ブラウザで、開始ページが開く。進め方は、次のとおり。

1. 開始ページで、入力（ファイルか、貼り付けたテキスト）・出力先のフォルダ（PPTX を保存する場所）・成果物の名前を選び、「回答をコピー」を押す。
2. Claude が、目的・対象・枚数・配色・テンプレートの有無を聞く。答えると、設計図と原稿ができる。
3. 全スライドの案を並べた HTML（`variants.html`）が、ブラウザで開く。左に一覧、右に 1 枚ずつ、スライドが並ぶ。
4. スライドごとに案を選び、「承認」を押す。最後に、「回答をコピー」を押す。
5. 選んだ案が、PPTX になる。Claude が、PPTX のパスと確認用の画像を報告する。

できあがる PPTX と、直しの元データは、開始ページで選んだ出力先（以下 `<出力先>`）に置かれる。

```
<出力先>/
  <成果物名>.pptx             成果物
  <成果物名>.html             出力形式が HTML か両方のときだけ
  pptx-deck-source/
    <成果物名>/               設計図・原稿・スライドの断片・回答など（直しの元データ）
```

注意: 同じ名前の成果物が `<出力先>` にあると、上書きするか、別の名前にするかを聞かれる。上書きを選ぶと、同名の PPTX と元データが上書きされる。残したいときは、別の名前を選ぶ。

### 用語

| 用語 | 意味 |
|---|---|
| 設計図 | 資料全体の結論と論点を書いた文書 |
| 原稿 | スライドごとの文章を書いた文書 |
| 型 | スライドの構成パターン（50 種類以上、たとえば比較表・手順図・グラフ） |
| デザイン | 同じ型の見せ方の違い（向きや配置の違い、型ごとに最大 3 つ） |
| 案 | 型の違う候補（A・B・C）と、自由設計の案（R） |
| 部位 | スライドの中の、題・本文・表・注釈などの要素 |
| 断片 | スライド 1 枚分の HTML ファイル（元データの `slides/` に置かれる） |
| 検査 | 文字のはみ出し・重なり・文字の小ささを調べる自動チェック |

R は、型にとらわれず、そのページの主張をいちばんよく見せる構成を、Claude が自由に設計した案。表紙・章扉・目次・裏表紙・クロージングの決定は、型が 1 つなので、案も 1 つだけにする。

### スライド案の選択画面

| 操作 | できること |
|---|---|
| 案とデザイン | サムネを押して大きく見て、案を選び、続けてデザイン 1〜3 を選ぶ |
| 承認・要修正 | 画面下のボタンで、承認すると次のスライドへ進む |
| 要修正 | 直す点を、コメント欄か部位のコメントに書いてから押す |
| 全部承認 | 案が決まっているスライドを、まとめて承認する |
| スライド全体のコメント | 画面下のコメント欄に書く |
| 部位のコメント | 題の右の「部位のバッジ」にチェックを入れ、スライドに出るバッジを押して書く |
| 編集モード | 題の右の「編集モード」を押すと、画面上で文字をそのまま打ち換えられる |
| 見どころ | 題の右の「見どころ」にチェックを入れると、見てほしい要素に枠と番号が重なる |
| 配色・文字サイズ・出力形式 | 画面上部で変えると、全スライドの表示がすぐ変わる |
| 回答をコピー | 回答がクリップボードに入り、Claude が受け取る |

R は、デザインを選ばない。Playwright MCP がないときは、コピーした回答を、チャットに貼り付ける。

### ほかの入口

| 入口 | 使う場面 |
|---|---|
| `/pptx-deck:revise` | 作った PPTX を直す（型・デザインの選び直し、文言・数字の修正） |
| `/pptx-deck:rebuild` | 元データ（`pptx-deck-source/`）を変えずに、PPTX を作り直す |
| `/pptx-deck:review-plan` | 設計図と原稿を、HTML で確認する（任意） |
| `/pptx-deck:diagram` | 型に当てはまらない図を、絵にする |

`revise`・`rebuild` は、`<出力先>/<成果物名>.pptx` のパスを渡して頼む。その隣の `pptx-deck-source/<成果物名>/` を使うので、PPTX を移動・改名すると見つからない。旧配置（`source` フォルダに元データを置く形）には、対応していない。

注意: PowerPoint で直した内容は、`revise`・`rebuild` では取り込まれず、作り直すと消える。直しは `revise` で頼む。他の人が作った既存の PPTX の編集には、使えない。

## 設定

| 項目 | 内容 |
|---|---|
| 配色 | `navy`・`green`・`gray`、または基調色（資料の主な色）`#RRGGBB` |
| 文字サイズ | 題・ヘッドメッセージ・本文・注記・出典・表紙の題と副題・小見出し・大きな数字・グラフ内の文字の 10 項目 |
| テンプレート | 16:9（13.33×7.5in）の `.potx`・`.pptx` |
| フッター | 左下に入れる文言（作成時に伝える） |
| 出力形式 | PPTX・HTML（1 ファイル）・両方 |
| `PPTX_DECK_HOME` | 専用環境の置き場を指定する環境変数（通常は不要） |

配色・文字サイズ・出力形式は、選択画面で変える。テンプレートのフォントと配色は使わず、フォントと配色は固定になる。

PPTX を作ったあとに文字サイズを変えるときは、`/pptx-deck:revise` の選択画面で変える。Claude が反映する。

文字サイズを大きくすると、文字が枠に収まらないスライドが出る。そのときは検査が止めて、PPTX は作られない。Claude が配置だけを直し、直せないスライドは報告する。

## 困ったとき

| 症状 | 対処 |
|---|---|
| 「実行できる専用の仮想環境がありません」と出る | 案内に従って、導入を承認する |
| 開始ページの一覧に、目的のファイルやフォルダがない | 一覧は作業フォルダの中だけなので、ほかの場所は、ページのパス欄にパスを書く |
| 開始ページを開いたあとに置いたファイルが、一覧にない | 「フォルダを読み直す」を押す（選んだ内容は消える） |
| 同じ名前の成果物があると言われる | 上書きするか、別の名前にするかを選ぶ |
| 「前回のビルドのあとに変更されています」と出る | 手直しを残すなら別の名前で出力し、消えてよいなら上書きを選ぶ |
| 「記録のない PPTX です」と出る（元の資料かもしれない） | 残したいなら、別の名前で出力する |
| 検査でエラーが出て、PPTX ができない | `revise` に頼んで、出力の違反（はみ出し・重なり・文字の小ささ）を直す |
| 文字の折り返しが、PowerPoint とずれる | BIZ UDPゴシックを導入する |
| 絵の中の文字を直したい | `diagram` で絵を描き直す（絵は画像なので、PowerPoint では直せない） |

入力に使った PPTX と同じ場所・名前には、出力できない。上書きを選ぶと、PowerPoint での手直しは消える。戻せないので、残したい PPTX は、先に別の名前で保存する。

環境の状態は、Claude に「pptx-deck の環境を確認して」と頼むと確かめられる。
