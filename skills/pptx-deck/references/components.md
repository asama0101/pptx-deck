# 型の一覧（`assets/components/`）

SKILL.md の 3 章から参照する。設計図の「型」はここから選ぶ。内容に応じた第 1 候補・次点は [patterns.md](patterns.md)（型の選定表）で決める。各断片の先頭のコメント（用途・差し替える所・デザイン 1 との違い）を読んでから使う。断片の部品の書き方は [html-rules.md](html-rules.md)。見本の画像はリポジトリ直下の `部品見本.html`（問いで分けた 9 区分に、型ごとのデザイン 1〜3 を並べてある）。

## 型とデザイン

部品庫は **51 型・147 本**。1 つの型に最大 3 つの**デザイン**がある。

- 型＝情報の構造（並列・手順・循環・グラフの種類など）。3 案（A/B/C）は型違いで出す。
- デザイン＝同じ型・同じ原稿のまま、形だけを変えたもの。型を選んだあとに選ぶ。ファイルは `<型>.html`（デザイン 1）・`<型>-d2.html`・`<型>-d3.html`。
- `cover`・`effort`・`relation` はデザイン 1 つ。そのほかの型は 3 つ。

## ページの共通の構成

本文の部品は、上から次の順に置く。

1. **題**（`data-role="title"`）: 名詞句 20 字以内。ページの主題。判断は書かない。
2. **リード文**（`data-role="lead"`、帯の中）: 判断を言い切る 30〜60 字。原稿の `見出し`。
3. **図表タイトル**: 対象・期間・単位の名詞句。
4. **本体**: 箱・行・棒のすべてに定量（金額・件数・日数・%）を 1 つ以上書き、本文領域の下端（y 640）まで使う。
5. **注**（`caption`）: 出典・前提・凡例。

**判断を求める型**（`decision`・`summary`・`decisions`・`argument`・`options`・`raci`・`actions`・`gantt`）は最下部に論点ボックス（パネル地の帯。「論点　〜の可否」1 行）を置く。それ以外の**情報の型**は帯を置かず、注の末尾を「→ 含意」の 1 文で締める。

## 9 区分と型

問い（何を見せたいか）で 9 区分に分ける。区分の中の使い分けは [patterns.md](patterns.md)。

### 1 ページの骨格

| 型 | 内容 | デザイン |
|---|---|---|
| `cover` | 表紙。題名・副題の位置はテンプレートで決まる | 1 つ |
| `agenda` | 目次。章ごとに結論 1 行とページ | 3 |
| `section` | 章扉。「章番号＋章の問い」、この章で判断すること、要点 3 つ | 3 |
| `closing` | 裏表紙。「本日のまとめ／次のステップ」。承認・報告・提案・研修に使える。デザイン 3 は問い合わせ先の帯つき | 3 |

### 2 判断を求める・要約する

| 型 | 内容 |
|---|---|
| `decision` | クロージング決定。決定事項の表・直近スケジュール・審議の基準・論点ボックス |
| `summary` | 数字サマリ・障害の概要。指標 3〜4 つと根拠。論点ボックス |
| `decisions` | 論点｜求める決定｜主要根拠｜詳細参照（エグゼクティブサマリ） |
| `argument` | 論証テーブル。課題→現状→打ち手を事実と含意の 2 段で |
| `options` | 案の評価表。評価軸×A/B/C 案、○△×と数値、推奨を強調 |
| `raci` | 役割分担表。工程×部門に ◎責任・○実行・△支援 |

### 3 同格のものを並べる・位置づける

| 型 | 内容 |
|---|---|
| `parallel` | 並列。同格の 2〜4 項目（横カード／縦行／格子はデザイン） |
| `positioning` | 4 象限。2 軸に施策のチップを置く |
| `venn` | 2 条件の重なりで候補を絞る。重複の整理にも |
| `text` | 文だけの説明。見出し＋本文×3（Q&A・アイコン付きはデザイン） |
| `screenshot` | 画面（キャプチャ）。並列／手順／拡大はデザイン |

### 4 前後・左右で比べる

| 型 | 内容 |
|---|---|
| `before-after` | 工程・体制・数量の前後。上下の箱／左右の対／時間比例の棒／積み上げ帯はデザイン。数字が前提 |
| `delta` | 数値の前後。現状→増・減→計画後と理由（設備の台数・見積の前回比） |

### 5 順を追う（手順・段階・繰り返し）

| 型 | 内容 |
|---|---|
| `flow-h` | 手順（横）。各段階に期間・成果物・承認点 |
| `flow-v` | 手順（縦）。段階が多く横に入らないとき |
| `flow-text` | 手順を文で読ませる。説明文と主な作業 |
| `flow-box` | 条件で分かれる手順。分岐 2 段まで |
| `swimlane` | 担当部門をまたぐ手順。横レーン／縦レーン／レーン×比例棒はデザイン |
| `steps` | 階段。段階が進むほど右上へ |
| `cycle-2` | 2 要素の往復 |
| `cycle` | 3〜6 要素の循環。輪／格子ループ／行＋戻り線はデザイン |

### 6 時間で測る

| 型 | 内容 |
|---|---|
| `timeline` | 発生順の事象。待ちの長さ・沿革。比例棒／表／表＋棒はデザイン |
| `gantt` | 工程×時間の予定。現在線と判断点 |
| `roadmap` | 年度ごとの設備の更改。増設・更改・撤去 |

### 7 構成・範囲を見せる

| 型 | 内容 |
|---|---|
| `architecture` | システム構成（層・上下）。デザイン 3 は層×系列の格子で自社の範囲を示す |
| `topology` | 拠点の接続系統（左右） |
| `org` | 体制図。責任者→PM→チーム |
| `enclosure` | 包括。外枠の中に子要素、その中に今回の対象 |
| `area` | 担当する領域。工程×担当で説明したい範囲を囲む |
| `site-matrix` | 配置表。拠点種別×設備の台数 |

### 8 要因・内訳に分解する

| 型 | 内容 |
|---|---|
| `tree` | ロジックツリー。要因を寄与で分解し、施策と評価列まで |
| `cause` | 原因の連鎖。事象→直接原因→背景要因→根本原因 |
| `formula` | 数式。結果を内訳の足し算・掛け算で説明 |
| `funnel` | じょうろ型。段階を経て数が絞られる |
| `pyramid` | 階層。上位ほど少ない・小さい |
| `relation` | 相互関係。窓口と関係者 2 者を矢印で結ぶ |

### 9 数値で見せる

グラフ 6 型は、デザイン 1＝全幅のグラフだけ、デザイン 2＝左グラフ＋右の内訳表＋基調色の帯、デザイン 3＝上グラフ＋下のカード＋合計カード。

| 型 | 内容 |
|---|---|
| `bar` | 縦棒。量の比較。注目する棒だけ強調（`highlight`） |
| `hbar` | 横棒。項目名が長い・項目が多い。現行と計画の比較や工数比較にも |
| `line` | 折れ線。時間の推移。系列は 3 本まで |
| `stacked` | 積み上げ棒。内訳の推移。系列は 3 本まで |
| `pie` | 円。割合。項目 5 つまで |
| `waterfall` | 滝。増減の道筋。見積の前回比にも |
| `cost` | 費用の表。費目×年度に 5 年計・構成比・累計 |
| `quote` | 見積明細。単価・数量・金額と見積合計 |
| `effort` | 工数。表＋比例棒（デザイン 1 つ） |
| `spec` | 項目一覧。検証項目・機能・要件。計画はデザイン 1、結果はデザイン 2 |
| `actions` | 対応一覧。再発防止策・課題・リスク（列見出しを差し替える） |

## 文書の種類と使う型

承認文書の種類ごとに、よく使う型。設計図の「型」はここから選び、足りなければ上の一覧から補う。

| 文書 | 冒頭 | 本体でよく使う型 | 結び |
|---|---|---|---|
| 稟議（投資・契約） | `summary`・`decisions` | `options`・`cost`・`quote`・`delta`・`waterfall`・`effort`・`hbar`・`actions`（リスク）・`flow-h`・`gantt`・`org` | `decision`・`closing` |
| 障害報告 | `summary`（障害の概要） | `timeline`・`cause`・`tree`（要因分解）・`before-after`（対応工程の改善）・`actions` | `decision`（恒久対策の承認）・`closing` |
| 検証計画 | `summary` | `spec`（検証項目）・`architecture`／`topology`（検証環境）・`org`・`raci`・`gantt`・`options`（方式比較）・`actions`（リスク） | `decision`・`closing` |
| 検証結果報告 | `summary` | `spec`（デザイン 2＝判定）・`bar`／`line`（計画値と実測値）・`actions`（不具合） | `decision`（次工程へ進む可否）・`closing` |
| 業務フロー | `section` | `swimlane`・`before-after`（現行と改革後）・`raci`・`cycle` | `decision`・`closing` |
| 設計書 | `agenda` | `architecture`／`topology`・`spec`（機能・要件）・`options`（方式比較）・`site-matrix`・`pyramid` | `summary`・`closing` |
| 設備増減の計画 | `summary` | `delta`・`site-matrix`（配置）・`roadmap`（更改）・`parallel`（左右の対比）・`stacked`／`waterfall`（台数の推移）・`cost`・`topology` | `decision`・`closing` |

内容に合う型がなければ、断片の部品（[html-rules.md](html-rules.md)）で組む。新しい型やデザインを作ったら、`assets/components/` に足し、先頭コメントに用途・差し替える所（デザイン 2・3 は「デザイン 1 との違い」）を書き、`check` で違反が 0 件になることを確かめる。
