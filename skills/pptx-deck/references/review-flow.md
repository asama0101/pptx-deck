# スライド案と最終 HTML のレビューの細則

SKILL.md の 3 章の手順 3〜8 の細則。ページの構成・ボタンの扱い・回答の書式・再提示・統合・最終確認。コマンドと待ち受けのコードは SKILL.md にある。

## 手順 3: ページを開いて伝える（`variants`）

`python "${CLAUDE_SKILL_DIR}/run.py" variants "<名前>"` → `<名前>/variants.html`。Playwright MCP の `browser_navigate` で `file:///C:/.../variants.html` を開き、「左の一覧から 1 枚ずつ見て、案を選び、直したい点はコメントに書いて、判断欄の右端の『回答をコピー』を押してください」と伝える。ページは、左に一覧（状態の点つき）、右に大きな 1 案と下に案のサムネ（押すと大きく見える）、コメント欄、前へ／次へ。見てほしい要素に付けた `data-note` は、枠と番号で重なる。ページの構成は、点検ページ（Artifact）と同じ。左に一覧（状態の点つき）、右に 1 枚ずつ縦に並べる（大きなスライド → 見どころ・前回のコメント・今回の直し → 判断欄）。スクロールして見る（1280×720〜1920×1080 で確認済み）。**`browser_resize` で窓の大きさを変えない**（窓とページの大きさがずれる）。3 択の下に「承認／要修正」のボタンがある（案を選んでいなければ、表示中の案が選ばれる。1 案だけのスライドはこのボタンだけで答える）。選んだラジオとボタンは、もう一度押すか「選択を外す」で外せる。「回答をコピー」は判断欄の最後の行（右端）にある（固定しない）。

## 手順 4: 「回答をコピー」を待つ

「回答をコピー」が押されるのを待つ（ユーザーに「完了」と入力させない）。押されると、回答はクリップボードに入り、同時に `window.__submitted` が立つ。`browser_evaluate` で次を実行し、送信されるか約 100 秒たつまでブロックして結果を返す。`submitted` が false なら同じ呼び出しを繰り返す（合計約 30 分、18 回まで）。ユーザーがターミナルに入力したときは待ちをやめて、その内容に従う。

`() => new Promise(res => { const t0 = Date.now(); const id = setInterval(() => { if (window.__submitted || Date.now() - t0 > 100000) { clearInterval(id); res({ submitted: !!window.__submitted, md: window.__answersMd }); } }, 500); })`

## 手順 5: 回答の保存と書式

`submitted` が true なら、`md` を `<名前>/answers-N.md` に書く（N は何回目か）。待ち受けずに、利用者がチャットに貼り付けた場合も、貼られた md を同じように書く。回答の形式は `## SNN` / `- 選択:` / `- 判定:`（承認・要修正。空でもよい。古い回答にはない）/ `- コメント:`。ボタンは「回答をコピー」の 1 つだけ（送信ボタンはない）。`finalize` は、判定が「要修正」のスライドも、コメントが残るスライドと同じく止める。

## 手順 6: 直して再提示する

**コメントがあるスライドだけ**、選ばれた案を直して 1 案にし（`NN-A.html` を上書き、`NN-B/C` は削除）、`variants --round N+1` で再提示する（「採用／要修正」の選択になる）。ページには全スライドが出るが、**利用者には直したスライドだけ答えてもらう**（ほかは前回の選択のまま。未回答でよい）。別案の希望があるときだけ 3 案に戻す。コメントが未反映のうちは `finalize` が止まる。再提示のページは、前回のコメントを `answers-N.md` から自動で出す。**直した内容は `<名前>/round-(N+1)-notes.md` に「NN: 直した内容」の行で書く**と、同じスライドの「今回の直し」として並ぶ（書かなくてもよい）。

## 手順 7: 統合する（`finalize`）

すべて決まったら、これまでの回答を**回の順に全部**渡す: `python "${CLAUDE_SKILL_DIR}/run.py" finalize "<名前>" --answers "<名前>/answers-1.md" --answers "<名前>/answers-2.md"` → `final.html`（`build` が使う素のページ。変えない）と、確認用の `final-review.html`。後の回答が前の回答を上書きし、選択が空のスライドは前の回答を消さない。

## 手順 8: 最終 HTML の確認（`final-review.html`）

`final-review.html` を `browser_navigate` で開き、「1 枚ずつ見て、『承認』か『要修正』を選び、『回答をコピー』を押してください」と伝える。待ち方と `md` の扱いは 4・5 と同じ（保存先は `<名前>/answers-final.md`）。『要修正』があれば、コメントに沿って `slides/` を直して `finalize` からやり直す。チャットで承認を受けた場合は、この手順は省いてよい。`finalize` を使わずにページだけ作り直すときは `review-final "<名前>" --answers …`（`finalize` と同じ引数）。
